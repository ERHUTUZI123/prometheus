# Original procedural-learning reading after the actual frontier pilot

These passages were personally entered by root after pilot execution, during constructive review010. They did not inform the frozen pilot; no retrospective provenance claim. The record is targeted, not a complete survey. No source code was run.

**SOURCE — Reed & de Freitas, Neural Programmer-Interpreters, arXiv1511.06279v4.** Read §3, §3.1 equations1–5/Algorithm1 and §3.2 equations6–8 in the [original technical text](https://arxiv.org/html/1511.06279v4). A shared LSTM core selects program keys, arguments and return. Calls initialize local hidden state; return resumes a caller saved on the stack. Program embeddings live in an extensible table. Training observes execution traces including next program, arguments and return; Eq8 factors their likelihood. Thus neural call/return, fresh per-call state, expandable programs and compositional memory reduction have explicit precedent. **RECONSTRUCTION:** v4 cannot claim those capabilities as its new mechanism. End-task learning of a credit-cost-sensitive organization would have different supplied information, but absence of trace labels is not itself a new acquisition algorithm. I have not checked all subsequent weak-supervision variants.

**SOURCE — Ellis et al., DreamCoder, arXiv2006.08381v1.** Read Wake/Sleep Program Learning, Eq1 and the Wake/Abstraction/Dreaming technical paragraphs in the [original text](https://arxiv.org/html/2006.08381v1). Task solutions, a library prior and a neural proposal distribution alternate updates. Abstraction searches bounded semantic refactorings of typed lambda programs, trading library/program description length; the recognition model learns from solved/replayed and generated tasks. Therefore it already changes the internal language and later search, beyond fixed program composition. **RECONSTRUCTION:** the v4 support/credit pressure differs from description length, but changing that objective alone is insufficient evidence of foundational value. A candidate must specify how learned neural proceduralization changes continuing learning or resource scaling. I have not read the supplementary refactoring dynamic-program derivation or run DreamCoder.

**OPEN:** Can a learned procedure carry a useful continuing-learning interface without maintaining all private state, and can the organization itself be acquired rather than supplied by a two-body cut grammar? The actual pilot does not settle this. A source-aware compiler given the resulting narrow learner exactly reproduces its retirement; that is a concrete shared mechanism, not a generic simulability argument. Further work must either construct the missing acquisition/organization rule or choose a different consequential question.
