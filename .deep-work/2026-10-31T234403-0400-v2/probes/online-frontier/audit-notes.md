# Independent design audit before pilot code inspection

Read-only audit of the active same-V2 mechanism: online-organization/candidate-v3.md, candidate-v4.md, root-credit-interface.md and online-frontier/contract-v1.md. Stage007 and previous fresh-principle artifacts were not edited. No experiment or new literature search. This is a preliminary design audit; code has not yet been supplied for inspection.

## Judgment

The contract supplies a coherent bounded physical-port experiment. Its central risk is concluding that an adaptation-aware projection demonstrates acquired procedural/credit organization when the executed system only learns a fixed low-dimensional summary of a supplied body under a fixed teacher span. That would still be useful intermediate evidence, with a narrower conclusion. The following are consequential implementation/admission checks rather than demands for universal representation novelty.

## 1. Actual native producer scope and versioned use

Check that all claimed plastic producer owners receive actual updates, not only calculated VJPs. The declared query partial derivative holds the adapted consumer state fixed; it is not the hypergradient through inner learning. If updates occur only after every outstanding object is released, report that finite scope rather than online producer plasticity across variable waits. If old objects survive an update, the actual array/version record must identify the gradient's source version and the rule for applying stale credit. Compare projected producer credit with full/native credit; matching only consumer loss misses the root example's decisive phenomenon.

Constructive fix: retain a clearly specified synchronized producer-version episode with one real terminal native producer step, report its exact scope, and evaluate the resulting next-episode computation/learning. An isolated VJP check validates code but cannot itself support continued-learning claims. Broader asynchronous version claims can remain outside this pilot.

## 2. Hidden information in lawful credit caches

Projection coefficients trained only during scouts and frozen in production must not retain an uncharged encoder Jacobian equal to hB. All production reachable arrays—including closure references and shared evaluation dictionaries—must be included or inaccessible to learner calls under the declared interface. Separating a nominal cache object does not prevent a hidden lookup into full hB/JB. Teacher/procedure-role data are evaluator-only, not proposal features.

Even correctly charged producer sensitivities can encode discarded forward information. For a one-step tanh producer

    h=tanh(Ux+b), z=r^T h,

the retained derivative rows obey

    dz/dU_ij = r_i(1-h_i^2)x_j,
    dz/db_i  = r_i(1-h_i^2).

Their ratio recovers x_j whenever the denominator is nonzero. For multi-step recurrence that direct formula no longer generally applies, but rP credit coordinates can still carry more information than the 2L raw inputs. No claim of forward erasure follows from a one-dimensional z.

Constructive fix: include a lawful cache-readable control using z, saved producer credit and retained versions; a scout-fitted reconstruction is a cheap diagnostic, not an optimal decoder. Alternatively state a shared typed-consumer restriction and limit conclusions to that runtime. Do not call the restriction an information lower bound.

## 3. Actual replay can dominate here

With six B coordinates and 54 B parameters, full output credit has up to 324 derivative scalars; a rank-r port has 54r. Raw replay needs 2L B input scalars plus a version checkpoint (which can be shared among all objects from that version). Depending on L and waits, even the projected credit cache can exceed honest raw retention. The A output/credit and all other common storage still count. Replay must recompute from the actual retained x and same producer version, not a hidden evaluator JB.

Constructive fix: show the complete memory-versus-feedback-latency frontier, including acquisition amortization over an explicit horizon. A formed port can remain valuable under a tight per-feedback compute limit even if replay uses fewer waiting bytes. Without such a declared constraint, a losing replay comparison is a real negative result.

## 4. Same-information adaptation-aware controls

Current-only compression is an admission negative control. The meaningful rivals are learning-continuation reduction and post-adaptation port learning with the same cut search, same legal scouts, same derivative access, same rank/cost menu and total formation budget. A minibatch-reuse inner loop should be named MAML-Rep-style, not exact OML reproduction. CoBRAS on an actual learning continuation may target the same missing directions; analytic teacher vectors must never initialize only one arm.

Constructive fix: preserve measured equivalence/ties when the ordinary control acquires the same port. The scientific intermediate result then belongs to the shared formation rule, not to an invented distinction between mathematically identical objectives.

## 5. Held-out demand must discriminate a future-credit interface

New seeds, input lengths and waits do not by themselves make a fixed learned projection support new learning directions. If every consumer target/composition lies in one preselected teacher span, a post-adaptation projection can solve the test without acquiring a more general credit organization. The source bodies, candidate boundaries and possible read sets are already designed, so this pilot cannot establish their autonomous invention.

Constructive fix: report the actual span/rank of evaluation consumer sensitivities and distinguish (a) compositions within the learned span, (b) new directions requiring honest reproposal/probation, and (c) unsupported already-erased objects. A legitimate failure in (b) should trigger a bounded future-call interface revision; it must not be repaired by retrospectively re-encoding old hB.

## 6. Physical memory is an array ledger, not an allocator claim

The pilot may count NumPy arrays exactly without claiming process RSS or hardware energy. Still separate waiting-state byte-time, peak arrays during producer/formation execution, shared parameter/version objects and per-feedback work. Avoid charging one identical version N times while sharing it elsewhere, or counting only a port's scalar values while omitting its retained derivative rows. Report actual code branch execution (early A return versus run-B-and-return) and do not substitute a mask-width proxy for it.
