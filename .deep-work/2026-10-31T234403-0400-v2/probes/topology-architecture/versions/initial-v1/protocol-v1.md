## Prototype and what is supplied versus learned

Prometheus is an end-to-end neural finite-state executor: trainable input-state encoder, token/task embeddings, learned call slots, learned latent operation matrices, recurrent execution and output decoder. No teacher operation matrices, correct intermediate states, correct routes or program words are supplied. Terminal examples contain only input tokens, initial operand, task descriptor and final operand. Latent operation matrices are learned from terminal cross-entropy, then interpreted as permutation/braid actions; their discrete classes and old reachable-state relations are extracted from the model, not handed to it.

The initial topological mechanism is a software quotient of the campaign's protected monodromy/operation representation. Nondegenerate learned assignment chambers encode operation classes. Old learned transition graphs are closed under their own learned generators; a finite old/new reachable-state relation checks encoder/decoder/call compatibility and all old input words without enumerating them. Continuous shared weights can change while the learned discrete computational class is retained. This is a provisional mathematical/software protection mechanism, not a demonstrated quantum realization or a verified new learning principle. Generic hard constraints, quantization, model freezing and topology must be distinguished by ablations. A conventional equivalence-constraint arm receives the same information and certificate opportunity.

Protection is consolidated only from actually trained models; it can preserve incorrect learned behavior and may restrict acquisition. Acceptance/rejection, graph sizes, maintenance calls/time and capacity increases are recorded. No manually supplied old correct state relation is used. Latent capacity growth is a declared possible repair, not evidence of autonomous discovery by itself.

## Fixed benchmark and comparisons

Three stages at operand sizes N=8,16,32 (powers of two), training seeds0,1,2. Software arithmetic teacher is experimenter-only. Stage0 tokens u=increment,v=bitrotate,n=identity; stage1 adds xor and affine arithmetic; stage2 adds a control token that toggles a hidden interpretation mode for subsequent u/v. Teacher mode is never an input/label to learners. All models see the same task ID, tokens, initial operand and terminal feedback. Stage2 requires latent memory; token lookup alone is insufficient. These are finite algorithmic tasks, not a claim of general open-ended computation.

Train4096 examples/stage, validation512, held-out IID512 and longer-composition512 per task; fixed distinct dataset seeds and recorded exact collision counts. Train length caps3/5/7; longer evaluation lengths8–12 (and a separate length16 level). Per-model maximum800 updates/stage, batch64, Adam, gradient norm cap1, evaluated every100 updates. Every method uses exactly the same minibatch indices/current-task samples; replay redistributes half the same total batch to old data. Its additional old-data access/storage is reported. No intermediate supervision. Dataset and evaluation hashes are retained.

Mandatory actual arms: (1) Prometheus protection, (2) Standard Transformer, (3) same Transformer+Replay, (4) same Transformer+Adapter, (5) same Prometheus without protection. Add (6) learned program-transition interpreter with modular protection, (7) same Prometheus with ordinary graph-equivalence constraint if implementable. Transformer uses real multihead self-attention, trainable positions/input/task embeddings, feedforward layers, and at least2layers/d48; adapters16 with a reused/warm-start head. All parameters/trainable masks, optimizer state and old-data resources are reported. Do not call the standard arm strong merely because it was coded: measure fitting/validation and allow the declared tuning/repair.

All arms get a small LR tuning opportunity (1e-3,3e-3) at N=8/seed0 on validation, max250 updates/stage/candidate, with pilot cost charged. A short smoke (N=4, <=120 updates/stage) checks actual gradients/learning/interfaces and is NOT M0 evidence. Formal grid uses the declared best validation setting. A capacity/credit-assignment repair is allowed after measured failure and must get a new version/output directory, with old raw data preserved. If losses/accuracy fail or protection stalls learning, at least one targeted correction is implemented AND actually retrained in this execution. No report-only repair.

## Outcomes and M0 gate

Record every evaluated learning point: terminal loss, current-task soft/hard accuracy, all old-task retention, unlearned-task performance, longer/unseen-combination accuracy, accepted shared updates, graph relation/call changes, operation reuse, model/optimizer bytes and inference/training/maintenance wall time. Shared-architecture changes cannot be inferred from parameter displacement alone. Track admitted learned operation classes and their executed compositions. Plot per-stage acquisition and forgetting; keep failures and confidence intervals across independent training seeds.

Evaluation reports the full task-by-training-stage matrix and length/scale strata. M0 requires all five human A–E conditions: meaningful continuing acquisition, old binding and multistep retention, reproducible important advantage over strong Transformer/continual baselines, multiple scales/complexities, and a causal protection effect. Small success, finite-state special advantage or a baseline failing to fit cannot pass M0. Replay/program/constraint explanations remain legitimate even if Transformer is worse. This protocol does not promise that M0 will pass.
