## Judgment and success counterfactual

The strongest conventional rival is **an autonomous coefficient editor with a continuation planner, followed by an incrementally compiled operation library**. It can propose new relation coefficients, find executable loops without receiving their desired permutations, select them by task feedback, and preserve old operations. It is not merely a predictor of an externally supplied cubic, and its library is not initialized with the correct new gate table.

One consequential condition topology could change is **retention under internal structural growth when continuous actuation really must execute**: can an agent acquire a useful new reachable operation by modifying its relation while retaining an already acquired algebra of old operations over permitted path deformations, without replaying every old composed task? That would connect directly to the fundamental question: internal computational mechanisms themselves can develop while their old executable meanings persist.

The present growth construction has a genuine mathematical consequence for that condition: a uniform corridor certificate preserves every word in the old generators, not just the tested words. However, a classical polynomial editor/planner can use the same certificate, and an immutable finite-state library preserves all old words algebraically. Thus this is a consequential property to pursue, **not yet a demonstrated advantage of neural acquisition or a new learning principle**. The acquisition-specific prospect must be lower total formation/maintenance cost, a broader learnable class, or a better justified generalization consequence than these explicit rivals. The current manually selected growth and critical-point-based loop do not establish any of those.

The concrete next acquisition action should select a growth/coupling and discover a useful operation from task feedback. Re-fitting the known source of the internally authored relation would not satisfy that action.

## 1. Fix the information contract before choosing a learner

Use one of the following cases, and state which one a result addresses.

| Resource or information | Internally authored relation: the central case | Unknown external relation: a distinct identification control |
| --- | --- | --- |
| Relation | The learner stores the source or coefficients it edits. The rival receives the same source/coefficients and update access. | Both receive the same observations of an unknown relation. Neither receives its hidden source. |
| Local observations | The same observed coordinates, task outputs and precision, including whether only the active branch or a whole fiber is observable. | The same selected-branch samples, residual queries, or whole-fiber samples; these are different interfaces. |
| Derivatives | Derivatives of one's own source can be computed by either side. Arithmetic/AD is charged. A derivative oracle is not an extra free observation. | Only the declared derivative oracle, finite-difference queries, or derivatives of the fitted model are available. They are distinguished and charged. |
| Task feedback | Endpoint reward/output or complete episode feedback, identically available. No desired loop, branch permutation, critical value, or new-state count is silently supplied. | Identical task feedback in addition to the relation observations. |
| Internal interventions | Both can edit the same coefficient class, add a branch under the same resource cap, and actuate the same control coordinates. | Neither may alter external physics unless that action is part of the environment. |
| Reset/initialization | Exact known initial state once; later resets require executed inverse words, paid homing, or an explicit reset service. | Same. Whole-fiber access is not inferred from seeing one root. |
| Semantic anchors | Old branch identities and the old acquired operations are the common starting mechanism. Migrating anchors after an edit is part of the cost. | Same starting knowledge; newly solved roots do not acquire old semantic labels for free. |
| Mathematical class | Monic holomorphic polynomial, degree/control-degree cap, precision and admissible corridor regularity are shared assumptions. | The same class restriction is shared if used to infer unseen behavior. |

If a neural relation is written by its own learner, hiding its source from the rival and then charging the rival for rediscovery creates an artificial acquisition advantage. If the relation is genuinely unknown external physics, recovering it is useful system identification, but that result must not be reported as autonomous construction of the agent's own relation.

Functional equivalence is a permutation on semantic branches at the resting control, together with required physical actuation if the task demands it. Coordinate displacement alone is not a new function. New useful functionality in the worked case means reaching the previously inaccessible rewarded branch by an operation that composes with the old one. It does not mean a new physical primitive or previously globally unreachable mathematical function.

## 2. Rival R: a conventional, autonomous polynomial editor and planner

Its persistent state is

    X = (theta, z_active, u_active, D, H, L, E, budget).

Here theta is the monic relation source; D is the data/task record; H stores branch anchors and known path correspondences; L stores acquired executable paths with their measured/certified actions; E stores protected corridor certificates. The active z is an actual transported state. H's virtual roots are metadata/model states and do not authorize teleporting the physical active root.

The following finite loop is an acquisition procedure, not an unspecified discover-controller.

1. Search bounded words in the acquired library against the new task feedback. A failure is a reason to consider an extension, not proof that every old word is useless.
2. Enumerate or learn a proposal distribution over a **shared finite mutation grammar**. One allowed proposal is multiplication by (z-r) and coupling by -epsilon phi(u); general monic coefficient edits within the same degree/bit budget may also be included. The choice of grammar is a designed inductive bias and is reported. The candidate receives no uncharged mutation policy absent from the rival.
3. Before committing, certify the protected corridor inequalities, including the coefficient-migration path and any admitted control deformation. Reject uncertified proposals or treat them as exploratory unsafe proposals; do not silently count pointwise samples as a uniform certificate. Both systems may use the same local bounds and interval/root-isolation tools.
4. Generate candidate closed paths by either of two conventional methods. **Model route:** compute critical points/values from the owned source, isolate them, construct handles that avoid the other critical values, and track roots to label the actual action. **Exploration route:** extend a graph of safe control vertices/edges, track unmatched known branches, and record any new correspondences or cycles. The rival may select the cheaper route. Global discriminant solving is not imposed when local loop exploration suffices.
5. Execute candidate paths/short words from the currently reachable state. Use the actual task reward to select a useful extension. No endpoint permutation label is provided by the task generator. Return by the reverse of the executed control/migration path when a reset is required and valid, paying its full execution cost.
6. Retain an extension only if it passes the task criterion and old-operation certificate under the declared resource account. Append the actual discovered operation and its evidence. Continue ordinary task learning only within the finite proposal/path/query budget; exhausting that budget reports failure/censoring, not impossibility.

The physically executed transition is the same one available to the topological candidate:

    dz/dt = -F_z^{-1}(F_u du/dt + F_theta dtheta/dt + kappa F).

Complex notation denotes the corresponding real-coordinate transition. Predictor/corrector implementation, conditioning checks, precision, correction tolerance and safe-step rules are matched. If the candidate finds a superior learned correction method or proposal policy, that is a possible contribution; it must be tested against the strongest version of this rival at equal information and total cost.

The rival does not require a membership/equivalence teacher. If only scalar task rewards exist, it uses those rewards and may fail. Adding such a teacher to either learner changes the task and the ledger.

## 3. Worked task-selected growth and operation acquisition

This example spells out an acquisition rival for the already inspected mechanism. Its success is derived conditionally; **the search below has not been run**. The saved experiment used a manually constructed B path and therefore is not evidence that this proposed acquisition search succeeded.

At rest u=1, begin with old P=z^2-u, active semantic branch 0 at -1, and an acquired path A around the old critical value. A exchanges branches 0 and 1. Permit a dormant branch r in a finite proposal set R, with r=3 one admissible proposal. The uncoupled source is

    Q_0=(z-r)(z^2-u).

The dormant branch is not reachable from the old active component by old control loops. A task supplies an endpoint acceptance sensor whose rewarded output is not obtained on either old branch. The learner is not supplied a target loop, transposition table, or critical point. For the r=3 worked branch, assume the task's acceptance set includes the migrated new resting root and excludes the two old roots. This is the declared task premise, not a result of the earlier experiment. If only output labels are requested digitally, section 5's table constructor may satisfy the same specification more cheaply.

The finite proposal grammar includes epsilon in {.005,.05,.2} and phi=1, with no preassigned new-operation label. A concrete controller can enumerate (r,epsilon), reject retention failures, enumerate the model-derived isolating loops and handles, then enumerate words of length at most two using A and one candidate loop. This is ordinary bounded search over **newly constructed operations**, not search over a fixed supplied braid alphabet. Its model-solve and rollout cost must be paid. Different mutation policies remain possible and are precisely what an acquisition comparison could investigate.

For r=3 and a safe positive epsilon, the owned source is

    Q_e=z^3-3z^2-uz+3u-epsilon.

The planner derives, rather than receives, its candidate singularities. Setting Q_z=0 gives u=3z^2-6z; substitution into Q=0 gives

    2z(z-3)^2+epsilon=0.

Thus one degree-three critical-point solve supplies candidate values. A small isolating loop around each regular simple critical value is a candidate; a handle and branch correspondence are still required. The source alone does not identify the useful endpoint action without solving/tracking or proving that correspondence.

Here is a concrete finite handle constructor. Isolate every critical value c_j. Rotate coordinates so that the real projections of all c_j and the resting control are distinct. Such a rotation can be selected from a finite list: for N distinct points there are at most N(N-1)/2 forbidden directions modulo pi. Choose circular neighborhoods small enough that their real-projection intervals are disjoint and exclude the resting control's real projection. Choose a horizontal line above all the disks and the resting control. Connect the resting control vertically to that line, then connect the top of each disk vertically to the same line. The horizontal trunk and these disjoint vertical stems form an embedded comb tree outside the disk interiors. For generator j, follow the tree to the top of disk j, traverse its boundary circle, and reverse the handle. The resulting based loops generate the punctured region's fundamental group when the region contains the tree and disks. All root isolation, rotation/clearance checks and path construction are charged. The region and minimum clearance are frozen before use; if these handles cannot fit inside the control/precision budget, the proposal fails. This gets paths from the owned model rather than a manually chosen useful B. Numerically uncertain critical locations require certified enclosures and inflated clearance, not a point estimate declared safe.

With access to such a complete critical-loop family in the control region, there is an additional algebraic check on completeness for this example. Q_e=(3-z)u+z^2(z-3)-epsilon is irreducible in C[z,u] for epsilon nonzero: any factor independent of u would divide both 3-z and z^2(z-3)-epsilon, whose gcd is one; a factorization of a degree-one polynomial in u must have such a factor. The regular covering is consequently connected and its monodromy action is transitive. Thus not every finite critical-loop generator can fix branch 2. The critical equation has no multiple root at positive epsilon: its derivative is 6(z-3)(z-1), while its values at 3 and 1 are epsilon and 8+epsilon. Distinct finite critical points cannot share a critical value here, since that would give a cubic fiber two distinct double roots. Its simple based critical loops are therefore transpositions, and one exchanges branch 2 with an old branch. From branch 0, either that loop alone or A followed by that loop reaches branch 2. This proves existence in the **complete model-derived family**, conditional on the stated region/isolation access; it is not a measured finite-precision search success.

The inspected analytic construction and saved summary establish that the existing chosen upper-new-critical-value handle has action

    A=(0 1),  B=(1 2),

with branch 2 descended from the dormant root. The saved B handle need not equal a newly generated handle: different handles can conjugate the transposition. The complete-family argument above is the rival's existence justification. A cheaper finite search over unrelated fixed polylines has no such completeness guarantee; the generated handles and their cost must be defined before an execution claims success.

The branch identity 2 here is identified by coefficient migration, rather than by sorting new roots and pretending coordinates were unchanged. From the initial branch 0, executing A then B reaches branch 2 and earns the new task reward. B alone would fix branch 0, so a search that tests each new loop only from the initial root could miss the useful operation. This is a substantive acquisition issue even in the cubic.

For the function convention used by the saved summary, words are executed left to right:

    AB: [0,1,2] -> [2,0,1],
    BA: [0,1,2] -> [1,2,0],
    AA: [0,1,2] -> [0,1,2].

The controller can now retain the new B path, not merely the rewarded AB episode. To identify B on all branches without arbitrary reset access, it reaches branch 1 using A and branch 2 using AB, queries B, and returns along actual inverse paths as needed. Alternatively, a valid proof that the isolated simple branch point exchanges exactly two identified sheets plus two paid branch tracks can complete the table. The remaining fixed point follows from a permutation; it is not a free extra task example.

This rival selects a coupling and an operation using task feedback while owning its relation source. Its editor, path search and retention certificate are explicit. The present topological candidate can implement the same acquisition scaffold. Nothing in this example yet predicts that a neural policy beats it. Conversely, the existence of the scaffold does not prove that every possible topology-aware learner lacks a resource advantage: the open issue is the actual cost and generality of the learned proposal/certification process.

The old saved run supports only the constituent growth/transport witness: safe epsilons retained A and enabled the chosen B; epsilon=4 lost A; the paid B constructor used one critical-point solve for each epsilon. It did not compare acquisition searches or prove B's retention through later learning. Its repeated seeds perturb controls; they are not independent learned proposal successes.

## 4. Identification control, with an exact sample contract

This is useful for detecting information asymmetry, but it is **not** the internal-growth success counterfactual.

Suppose the unknown external relation lies in the shared class

    F(z,u)=z^3+(a0+a1 u)z^2+(b0+b1 u)z+(c0+c1 u).

Each observed exact zero (z_i,u_i) yields one linear complex equation with feature row

    (z_i^2, u_i z_i^2, z_i, u_i z_i, 1, u_i)

and target -z_i^3. Six independent rows identify the six coefficients. There is a particularly transparent sufficient design: observe all three distinct roots at each of two distinct regular controls u0,u1. If two candidate models agree on those observations, their difference is a degree-at-most-two polynomial in z vanishing at three distinct points at each control. Its three coefficient functions therefore vanish at both controls; being affine, they vanish identically. Identification is unique in this class.

For the worked Q_e, the recovered coefficients are a0=-3, a1=0, b0=0, b1=-1, c0=-epsilon, c1=3. These are an outcome of the specified noiseless information contract, not an empirical fit reported here. Derivatives need not be provided; they follow from the recovered source with charged arithmetic.

Costs hidden by the phrase six samples can dominate. Whole-fiber observations at two controls could require two paid cubic root solves or many paid continuation experiments. If the interface exposes only one active root, the design cannot request the other roots for free. Six generic selected-branch samples can also suffice if the feature matrix has rank six; that rank is checked, not presumed, and conditioning controls noise amplification. Finite noisy fitting provides neither an exact polynomial identity nor a corridor certificate without further error bounds. If the relation is internally authored, all this recovery is unnecessary and neither side receives credit for rediscovering its own coefficients.

### Why local evidence alone cannot promise an unseen operation

There is a direct indistinguishability construction if no shared degree/control-degree restriction or global error certificate is assumed. Let finite sampled controls be u_i, with local derivatives through order m supplied. Define

    H(u)=product_i (u-u_i)^(m+1),
    F_0(z,u)=z^2-u,
    F_lambda(z,u)=z^2-[u+lambda H(u)].

All these models agree on the observed fibers and on every provided derivative through order m at those controls. Pick a nonzero unobserved u_* with H(u_*) nonzero, and choose lambda=-u_*/H(u_*). Then u+lambda H(u) has a zero at u_*. For a generic choice of u_*, its derivative there,

    1-u_* H'(u_*)/H(u_*),

is nonzero. A sufficiently small loop around u_* has identity monodromy for F_0 but a transposition for F_lambda. This is an exact algebraic ambiguity, not a statement that a trained learner will encounter that adversary. The second relation may have higher control degree; a shared fixed control-degree class excludes this particular ambiguity. Consequently, generalization from local relation data to global operation discovery needs a stated class/error assumption. Neither a neural residual nor a polynomial compiler escapes that information requirement by calling it emergent topology.

## 5. Rival C: compiled operations, with two different execution contracts

After acquisition, store semantic state s in {0,...,n-1}, generator tables T_j, and a program word. For the worked example,

    T_A=[1,0,2],  T_B=[0,2,1],
    s_next=T_j[s].

These tables are acquired by the paid process above; they are not initial answers. Composition then needs no word-specific labels. A full length-l word is evaluated with l table accesses for one active state. A full permutation can be compiled using O(n*l) accesses, or simply retain the word. A k-generator library needs O(n*k*log n) bits for dense tables, plus state bits and any stored words. Storing all n! permutations is unnecessary.

**Digital functional task.** If only the discrete answer matters, C can execute the table transition directly. It bypasses all root tracking, numerical conditioning, coefficient migration and anchor sensing after compilation. This is a valid and likely cheaper rival for that task. A continuously represented internal relation must justify any additional acquisition/generalization benefit against this execution advantage. Calling that bypass ineligible would change the problem after seeing a strong baseline.

**Same continuous actuation task.** If the retained physical/continuous z must travel through the same relation and control channels, C uses its table for planning but executes the same acquired path, tracks/corrects the same actual root, and observes the same anchors. A discrete label update cannot move z. No energetic, speed or numerical advantage over an equal continuation executor is assumed. Conversely, the topological candidate cannot count the baseline's table and also forbid it the same path/certificate metadata the candidate retains.

When a new branch is added, the compiler extends each old T_j by fixing the new label, and appends the acquired new table. Old table entries remain immutable. This preserves every old word without replaying it. The compiler does not thereby prove that the **physical** paths still realize those tables after a source edit; that additional obligation uses the same corridor certificate or paid revalidation as the topological candidate. This distinction prevents an artificial digital-retention victory from being mistaken for physical-retention evidence.

## 6. Full resource ledger

Report a vector first; choose any scalar tradeoff before evaluating. One possible account is

    C_total = w_obs N_obs + w_der N_der + w_goal N_goal
            + w_crit C_critical + w_root C_root + w_fit C_fit
            + w_F N_F + w_J N_J + w_lin C_linear + w_cert C_certificate
            + w_act L_actuation + w_reset L_reset + w_store M_bit*time.

Weights express the application; they are not measured energies. Degree, precision and condition numbers accompany the counts. A critical-root solve is not a unit-time oracle just because it is called once. Also report peak storage and hard caps separately from the scalar account.

| Item | Charge and matching rule |
| --- | --- |
| Local evidence | Every residual/coordinate sample, active/fiber observation, reward query and failed proposal. Synthetic samples from owned source are computational work, not external evidence. |
| Derivatives | Source AD/symbolic evaluation, finite-difference residual calls, or external derivative queries separately. Hessians/critical Jacobians are not silently included in one first-derivative call. |
| Critical/root solves | Degree, precision, Newton iterations/evaluations, isolation/certification and failed solves. The worked model route uses the cubic 2z(z-3)^2+epsilon=0; the exploration route may avoid it but pays its rollouts. |
| Tracking | Predictor steps, rejected/halved steps, residual/Jacobian evaluations, linear solves, corrector iterations and tolerance. Count actual and virtual branch tracking separately. |
| Growth and migration | Proposal construction, certificate computation, coefficient path, active-state migration, semantic-anchor migration and decoder update. New root solving is not a semantic reset. |
| Library acquisition | Candidate-loop/path design, branch-correspondence tracks, reward rollouts, unsuccessful words, full/partial table compilation and branch access. |
| Retention | Uniform certificate computation or paid old-task rechecks, including admitted path deformations and later source changes. The earlier proof does not certify arbitrary later edits. |
| Composition | Word search/planning, table actions, optional full-permutation compilation, and physical execution of each primitive when required. Do not charge the candidate only a final compiled answer and the rival every intermediate operation. |
| Reset | Actual inverse path, homing episode or explicit reset service. Reversibility applies only while the executed relation/path is regular and known; an environment reset is a separate capability. |
| Storage | Coefficient/NN parameters and optimizer state, samples, anchors/uncertainty bounds, paths/graph edges, tables, certificates and compiled words at the same precision. |

The existing summary's steps/corrector/oracle counters and constructor-critical-solve field are evidence for that old implementation only. The global state-root oracle was a verifier there. If any acquisition controller uses that oracle to select paths or identify target branches, its calls become acquisition costs; they cannot remain labeled verification-only. The summary is not a complete neural-versus-rival acquisition ledger.

## 7. The one consequential topology condition, derived and falsifiable

Let C_s identify old anchors through a regular coefficient homotopy. For each acquired generator j, suppose a **uniform** certificate establishes

    T_(j,s) C_s = C_s T_(j,0)

on the old branches for all admitted source/path deformations. For any finite word w=j1...jl, repeated substitution gives

    T_(w,s) C_s = C_s T_(w,0).

Thus one protected generator family retains all its compositions, even though coordinate values move. This does not require testing every word. The bound in post-execution-certificate.md supplies an instance for the old A family over the declared safe perturbations. It does not yet supply repeated task-selected growth or preservation of the newly acquired B.

The consequential condition is therefore precise: **repeated task-selected relation growth must add useful executable reachability while a finite, affordable, source-valid certificate preserves the old generator algebra over the stated continuous deformation family.** That would change how a continually modified computational substrate can retain its mechanisms. An important possible failure is that certificate/conditioning/anchor costs rise so quickly with growth that retention is formally true but no more accessible within the resource budget.

Before a confirmatory run, freeze task distribution, old operations, allowable edits/deformations, finite degree/precision/query/actuation/storage caps, and whether output is digital or physical. Hold out new compositions separately from old retention. A candidate success requires actual task-selected new growth/operation, migrated-state execution, retained old semantics, and the complete ledger. Its advantage criterion must name a budget-to-acquisition or certified-generalization difference against **both** R and C where their execution contract applies. Neither word count nor passing more sampled compositions substitutes for that difference.

Precise ways this condition or the proposed advantage fails:

- **Retention claim fails:** an allowed edit/path deformation with a genuinely valid claimed certificate changes an old generator under migrated semantic labels; then the claimed certificate/transition implementation is wrong. If the certificate cannot be established, report unresolved retention rather than a false pass.
- **Acquisition claim fails:** the procedure needs the hand-selected useful critical value/handle, desired transposition labels, an uncharged reset, or a hidden source/whole-fiber oracle unavailable under the contract. A successful manually supplied B remains a construction result.
- **Resource/usefulness claim fails in the stated family:** R acquires the same useful extension and preserves/composes it within the same caps and with no worse predeclared total cost, or digital C satisfies the complete task at lower total cost. This falsifies an advantage claim for that family; it is not a proof that topology can never matter.

The constructive rival already shows why the present cubic is insufficient to claim a learning advantage: its source, critical equation, retention bound and discovered permutation library can all be used by a conventional coefficient editor and continuation planner. The live question should therefore concern the autonomous proposal/certification law under a consequential sequence of growth tasks, rather than re-demonstrating cubic root tracking or merely changing which network represents known coefficients.
