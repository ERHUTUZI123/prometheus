## Actual computational and learning rule

The supplied substrate is the three-sheet cover

\[
z^3-3z-u=0,
\]

with critical controls ±2, fixed starting-sheet encoding/readout and triangular loops

\[
\gamma_a:0\to a+i\to a-i\to0.
\]

The executor genuinely follows all three roots through each segment using a safeguarded predictor/Newton corrector. It carries sheets through concatenated calls. It does not consult an execution table of desired transpositions. Full-fiber endpoint observations are deliberately returned and charged to **all** arms, so this is terminal-label supervision with full-fiber execution observations, not a single-sheet-only observation protocol.

The shared controller is

\[
a_{old}=w_0,\qquad a_{new}=w_0+w_1,
\qquad (w_0,w_1)=(-3,4).
\]

These features are nonorthogonal: a new-task gradient changes the old loop too. The old action B=(12) is **seeded** by this initial controller and checked by actual continuation; it was not learned in an earlier task stage in this diagnostic. The new loop initially has identity action. Four supplied terminal training examples demand a new A=(01) action, which is outside the old admitted subgroup `{I,B}`. Four held-out initial-state/word cases test its composition with B. The family, polynomial, features, fixed E/R, task words and their feedback are designed ingredients; the learner is credited with selecting the new loop class inside this supplied family, not inventing the cover or all calling syntax.

The raised-cosine location kernel is normalized, with an explicitly checked untruncated support box. A coordinate estimator evaluates safe representatives of the chambers adjoining detected branch-crossing events:

\[
\partial_a J_\sigma=\sum_r(L_r^+-L_r^-)p_\sigma(b_r-a).
\]

Then actual NN backpropagation maps that action gradient to its shared weights, followed by a guarded explicit SGD transaction. For the real four-example objective at the initial mean, the jump at+2 is−.75 and the initial gradient is **−.1875**, not the single-example proposal's−.25. Raw logs contain the actual−.1875. The terminal loss's ordinary within-chamber derivative remains zero; this stochastic/boundary objective supplies the class-changing signal.

Old-loop protection combines the sufficient same-homotopy test `maximum vertex displacement < previous loop clearance` with newly paid checks for the executor's finite .015 clearance and control-coordinate box. This fixes the earlier static issue that positive topological clearance alone need not meet the numerical execution contract. Exact real-arithmetic semantics are conditional on these geometric rules; the numerical continuation checks are not interval certification.

### What the score censor means

The score arm has13 genuine learning-curve records in the raw file, all with old loss0; its result object omits the in-progress trajectory but does not erase those records. Its last safe state is `(-4.643788325061026,2.356211674938974)`, independently present in the partial NN ZIP. It did not acquire A before a randomly sampled proposed loop violated the .015 executable-clearance policy. That is a **numerical/feasibility censor**, not an established negative task-success result or a failure probability of score-function learning.

The ideal kernel objective assigns mass arbitrarily near a branch boundary, while the practical executor excludes a positive-width finite-clearance band. Event integration can infer chamber losses from safe representatives; direct score sampling can land in that forbidden band and stop. Thus the finite-execution interface/proxy distinction matters. Do not report event's completion versus this single score censor as a fair statistically established gradient-learning advantage. A future score repair must specify its feasible distribution or paid chamber substitution without silently treating rejected probes as zero loss or dropping their contribution. The exactly matched ordinary-event control already covers the event-aware alternative.

The reported sample variances0 versus .02513949 use only three initial estimates. The event value is deterministic on this1D slice; those numbers alone establish neither an equal-cost statistical advantage nor performance in a multi-coordinate controller.

## Scientific judgment for the fixed TODO scope

**Actual advance:** the NN's continuous path outputs now acquire a discrete executable class through paid terminal feedback, and a sufficient geometric transaction preserves an old class despite shared-weight changes. This is a real new executed learning rule relative to the campaign's map-first renderer. It deserves development rather than being dismissed because known operations can simulate it.

**Remaining central uncertainty:** whether this organization changes acquisition, long-term retention, verification or parameter growth beyond ordinary event-aware program learning and strong discrete/constraint strategies. Here the discrete method is cheaper, the ordinary-event method is identical, the old primitive is seeded, state dimension and E/R are fixed, and the instance has only three readily enumerable chambers. Neither an architecture-level win, long-term continual acquisition nor a general Block is demonstrated.

The next consequential development should preserve the useful class-learning rule while examining a case where representation/feedback structure makes the ordinary cost tradeoff genuinely uncertain, keeping the strong event-aware and discrete alternatives.
