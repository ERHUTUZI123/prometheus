## Source boundary actually entered

I read the original *Meta-learning Symmetries by Reparameterization* §4, equations (2)–(4), Algorithm 1, and §5.1's actual MSR-Joint definition. MSR learns U separately from per-task parameters; standard transfer freezes U, while MSR-Joint updates U and v on task training data. Directed or asymmetric effects alone do not establish novelty: even a familiar symmetric update kernel can yield asymmetric task utility in different recipient states.

## Precise state and cycle

**AGENT PROPOSAL, not an executed result.** Let Theta collect the actual independently owned position parameters. A position may be a nonlinear cell called inside several programs, not an externally supplied task identity. Maintain:

- an observable context c_j derived from current program structure and execution;
- an explicit history state h_j recording available experiences and actual intervention outcomes;
- a packet proposer `delta_j=T_phi(c_i,h_i,c_j,h_j,u_i)`;
- a separate finite-effect predictor `Q_psi(c_i,h_i,c_j,h_j,u_i,delta_j,step_context)`;
- bounded episode memory with actual packets, versions, outcomes and measured costs.

Updating psi or h alone changes future learning decisions while leaving current forward parameters Theta unchanged. That is a real separation of execution from learning state. It is not by itself a new mechanism: learned optimizers also have such state. The object must earn its value through acquisition, transfer and revision.

### 1. Obtain an actual source experience

An external-output training example for an active program produces a legitimate base update u_i at an active position i. Ordinary AD is allowed. Apply the source's native update under the declared rule, giving the common reference state `B_i(Theta)`. Recipient proposals should all be defined relative to this same reference, not one branch before and another after source learning.

Normalize parameter-role references to physical owners first. A repeated read of one owner is not an independent recipient, and a packet writes that owner only once. P's alias-aware specialization remains relevant here. State the affected consumer programs conservatively; validation of one caller cannot silently stand for retention in every other caller.

### 2. Predict a finite intervention, not an association label

For a candidate bound packet delta_j at recipient j, define its measured gain at the reference state by

```
Y_ij = V_j(B_i(Theta))
       - V_j(B_i(Theta)+E_j delta_j)
       - lambda * max(0, R_j(B_i(Theta)+E_j delta_j)-R_j(B_i(Theta)))
       - charged_action_cost.
```

Here V_j is the declared external-output loss of the consumer programs relevant to the current acquisition objective; R_j is the retained-program loss under the stated coverage. E_j binds a packet to its real owner coordinates. Positive Y is beneficial under this objective. If the pilot uses separate current/retained losses rather than a scalarized objective, preserve the vector and use the frozen acceptance rule instead.

This is a **finite causal effect of a specified packet**, not a hidden “correct recipient” group supplied by the generator. It is conditional on current state, packet magnitude/direction, consumer context and the evaluation distribution. A first-order gradient inner product can be a baseline predictor, but it is not the label.

### 3. Acquire effect evidence through paired replay

Replay packet and sham from the identical saved reference, on the same evaluation examples and coupled randomness. Record both losses and the actual finite difference. A matched-norm random or sign-reversed packet is a useful control when included in the fixed budget. Every sham/packet evaluation, checkpoint, label query and candidate activation is charged.

Training records must contain the **actual executed delta_j**, its norm, source/proposer version, context/history snapshot and applicable owner binding. Changing T_phi later must not relabel an old effect as the outcome of the new packet. This is why proposer and effect predictor should be separate objects. The first pilot may use a small declared packet family while learning recipient selection; learning a larger transformation policy can follow only if that further construction is justified.

### 4. Learn, explore and revise

Train Q on observed finite effects, including harmful and null outcomes. Update h_j from observations that were actually obtained. Use a declared small exploration probability or query allocation so that a mistaken negative association can be challenged; a purely greedy predictor never observes some of its own errors. Record selection probabilities when estimating policy-wide averages from selectively queried episodes.

Surprise updates the association/history and can prompt a new response probe or a different packet proposal. Surprise is not itself evidence that a particular latent group changed. The policy may refrain from routing when evidence is weak; abstention and missed opportunities must be counted.

### 5. Propagate with a paid check

Select few predicted beneficial routes. Initially apply one recipient at a time, or recompute and validate after each accepted route. Single-edge benefits need not add when recipients interact through a composed program, even with independent parameter storage. A sum of individually predicted gains is not a certificate for a joint route bundle.

Evaluate actual later task acquisition and retained behavior, not only Q's predictive loss. The learned association earns value only if its formation and query costs improve the subsequent learning process at the declared budget.

## A meaningful minimum test family

Use **independently parameterized nonlinear cells inside externally supervised composed programs**. A controlled generator may reuse several latent nonlinear ingredients, for example small residual neural maps composed in different orders/contexts. Its ingredient IDs, desired recipient partition, target local cell outputs and generating parameters are withheld from every learner. Learners receive the same program structure, external input/output examples, permitted behavior probes and experience history. No method receives hidden local targets while another is denied them.

The latent ingredients provide one possible reason transfer is useful; they must not be readable from a coefficient such as b_i or an exposed recipe label. Different current parameter states and consumer contexts must make the effect of a packet nontrivial even among positions associated with the same ingredient. This remains a controlled pilot, not proof that the family captures the full scientific problem.

The pilot should include three finite stages within one contract:

1. **Acquire/calibrate on old positions.** Record actual nonlinear packet/sham effects. Demonstrate that predictions change with packet sign/size and current recipient history where the executed outcomes require that change. A table keyed only by position/task ID should be unable to explain the held-out effect pattern by construction; do not infer the candidate succeeds merely from that fact.
2. **Transfer the learned association rule.** Freeze its shared parameters before adding genuinely new cells and new program compositions. Randomize position IDs. Allow only a predeclared small amount of new-position context/history calibration, equally available to competitors. Predict new packet outcomes before observing them. Reusing old IDs or relabeling the same graph is not structural transfer.
3. **Revise online.** After an informative change in experience/consumer context, compare the updated history/rule against a frozen stale-association replay at common parameter checkpoints. Both arms receive the same new observations. Do not demand correct revision before any observation distinguishes the changed situation. A negative-control stream with unrelated ingredients should expose indiscriminate broadcasting.

Evaluation should report held-out program loss and retention versus **total** source/recipient forward, backward, replay and calibration work. Effect-sign calibration or ranking is useful diagnostic evidence, not the ultimate success criterion. Additional learned feedback state, candidate features, caches and position descriptors are real storage/computation.

This family tests a different content from fitting a static sharing schema: the output label is the realized effect of a particular learning packet through a nonlinear recipient and its consumers, and the association must survive new positions and revision. It still may reduce to known model-based learned optimization; that is a real possibility to assess after the constructive execution.

## Actual strong controls

- Native local learning with no transfer, budget-matched generic broadcasting and a static learned affinity provide causal ablations.
- A first-order/task-affinity predictor may obtain current recipient gradients under the same information interface, with their acquisition/evaluation costs charged. Do not give the candidate free validation caches or charge only the baseline for its necessary probes.
- Include the actual MSR/MSR-Joint or a clearly labeled comparable adaptive sharing implementation where its fixed parameterization applies. When positions are added, give the baseline a legitimate inductive extension; winning only because a frozen matrix has no rows for new IDs would be an architecture mismatch.
- The strongest learning comparison is an equally trained context/history-conditioned kernel or graph learned optimizer given the same episodes, packet family, candidate activation rights and budget. A model-based Q with explicit effect supervision is a proposed component, not a capability unavailable to a generic optimizer. If the latter learns the same behavior at the same cost, state that outcome without a universality veto or a renamed contribution.

The objective is not to manufacture separation by denying a baseline the learning signal. It is to discover whether this organization of executed effect evidence and revisable recipient state supplies a consequential acquisition/resource tradeoff.

## One fragile premise and a constructive repair

**Fragile premise:** the observable context/history is informative enough to predict a packet's finite effect at a new position. The earlier K and P analyses give a concrete warning: identical current execution descriptors can hide different update responses or owner bindings. If two positions have indistinguishable available h but opposite packet utilities, regression cannot recover the missing distinction without new evidence.

The constructive response is to pay for a small recipient response probe, retain the resulting learning-state distinction, or express packets in explicitly calibrated local edit ports instead of assuming raw weight coordinates correspond. For example, a few measured responses to named local edit directions can refine h; a source packet can then be described by its observed effect at those ports. The same calibration must be available to competitors. This is a repair route, not a claim that a few probes identify every nonlinear mechanism or that the old history has reappeared.

Do this constructive pass before treating an identification failure as closure. Conversely, do not promote inaccurate effect forecasts to established associations or protect a representation after a decisive same-information contradiction.
