# Prometheus · 拓扑回溯与审查制度修订

## 部署范围与权限

用户已明确决定：**拓扑计算为主攻方向；没有后续明确的人类命令，不允许改变。** 本包把该决定落实到常驻宪法、研究流程、子代理分工和恢复规则。它不要求得出有利于拓扑的结论，不否定旧审查中的有效反例，不增加任何资源/模型/收费/系统权限。

本包只生成并验证了对三个已知文件快照的修订：AGENTS.md、deep-work/WORKFLOW.md、deep-work/ROLES.md。当前 MacBook 的真实版本尚未读取或修改。reference/ 是修订后的参考文件，不能直接覆盖后来改过的本地文件。

## 在当前主会话执行

1. 先核对项目位置、当前 AGENTS/WORKFLOW/ROLES、唯一主 NOW、campaign state/checkpoint、未提交改动和活跃任务。研究视野、永久原则、原始资料和历史结果保留。安全保存尚在运行的 Persistent State 子任务，暂停它的独立后续派发；Online 继续 USER-PARK。
2. 对照 BASELINE.json。若三个文件逐个与 before_sha256 一致，先 `git apply --check prometheus-topology-return/topology-priority.patch`，通过后才 apply。若不同，读取 patch 和 reference 的政策差异，逐项语义合并；不要强制 patch、reset、checkout、丢弃本地修改或覆盖整份文件。
3. 若该包已经合并，不重复添加规则。无论何种方式，检查原有“自主换主线”“不预设基底”“不同候选重新选题”等语句在当前 USER_LOCKED_TOPOLOGY 下均有清楚限定。永久原则逐字不变，安全/证据要求继续生效。
4. 在现有主 NOW/state/checkpoint 记录当前人类决定及版本；不要覆盖全部 NOW，不篡改旧封存报告，不新建第二套计划。若存在 campaign 内 supervision/instructions-v1.md 或同类正在生效的指令，只做本次所需的权限/审查范围同步，保留其本地其余规定。历史 review 保持只读。
5. 向实际活跃监督者/子代理派发新优先级包并确认接收。旧会话无法更新时，先保存其进展，再在新上下文加载新规则。不要假定只改磁盘文件就自动改变了所有已启动子代理的指令。清理尚未开始的跨主线任务；不重复实验、不补造已丢审查。
6. 沿用当前有效授权宿主和资源，不通过本次部署切换模型或开启新付费调用。检查补丁落实后，只简短报告修改，然后**立即恢复同一 V2 的拓扑实质研究**，不把政策部署作为研究结项。若执行环境确实阻塞，明确写出阻塞，不假称后台运行。

## 第一个科学动作

读取拓扑相关实际候选及 Review011–013 的范围。用现有候选文件的一小段建立证据对应：已验证的条件性保持；已验证的有限操作获取；仍未直接检验的持续适应/保持总成本假说；被否定的具体版本。

随后选一项核心未知做连续构造：受保护参数变化能实现什么真实有用的学习，怎样在新能力/适应与旧语义保留之间定义可测的权衡。第一阶段可以是推导或诊断，不要求先给出完整新算法或胜过基线。不能只复制旧的有限置换任务、多跑种子，或凭“经典实现也能用同一证书”把待检验主张关闭。

独立审查必须注明测试是否 DIRECT/PARTIAL/OUT_OF_SCOPE。给出真实传统竞争方法、同机制实现和机制消融各自的作用；不禁止合法的数字表/冻结/回放/模块方案。反例仍有效，结果可以完全不利于拓扑。若无可推进的主线内动作，保存检查点并提出方向建议，由人类决定，不自行换 MAIN。
